## 一、失衡条 → 失衡硬直 → 连携技（P0，ZZZ 战斗循环的心脏）

### 1.1 目标

复刻绝区零的核心循环：**攻击积累失衡值 → 失衡条满 → 敌人进入失衡硬直（长硬直 + 伤害加成窗口）→ 连携技触发点 → 大招/喧响资源回收**。没有它，战斗只有"打→闪→还手"的平面循环，没有高潮点。

### 1.2 框架与结构

**数据（Luban 表，禁止手改导出物）：**

| 表 | 新增字段 | 说明 |
|---|---|---|
| `SkillDamage`（段表） | `DazeValue`（每段失衡贡献，可选列，0=不贡献） | 数字源头；表现不读 |
| `RoleAttri` 或新 `DazeSetting` | 失衡条上限（按敌人档位）、失衡持续时间、失衡伤害加成系数 | 杂兵/精英/Boss 各一档 |
| 新 `ChainSkillSetting` | 连携技列表：`SkillId`、触发条件、演出包 | 连携技就是普通技能轴 + 入场包装 |

**组件（ACT 层，参照 `CombatPoiseComponent` 的位置与写法）：**

- `CombatBreakMeter`（挂 `CombatEntity`）：只存一条浮点计量（上限 + 当前值 + 贡献源缓存）。**明确不是 TimeBuff、不进 `IdStatuses`**（Buff 文档 §4 硬约定）。暴露 `AddDaze(value, source)` / `CurrentRatio` / `NotifyBreakMeterOpened` 事件。
- 敌人 HFSM 新增两个战术态：`Stagger`（失衡硬直，空转、面朝玩家、可被处决窗口触发）与 `Punish` 对应导演侧节奏态。
- 导演 `CombatEncounterDirector` 复用预留接口：`NotifyBreakMeterOpened` → 全局进入 **Punish Tempo**（预算 0，其余敌人不抢戏、不打断），AI 文档 §4.2 已定义语义。

**表现（走 `CombatPresentationDirector`）：**

- 失衡条满瞬间：复用 `StaggerBreak` 表现包（强 HitStop + 闪白 + 最重震屏，已存在）追加"破衡爆闪"与失衡条破裂特效。
- 失衡期间 UI：敌人血条下专用失衡条（不是 Buff 图标栏）。

### 1.3 整体流程

```
伤害结算 DamageAction（段表带 DazeValue）
  → CombatBreakMeter.AddDaze（可被敌人失衡抗性缩小）
  → 条满 → 结算后置点通知（不入伤害热路径）
      → CombatStateDirector：BreakSkill → 写 CurState=Stagger（失衡硬直）
      → 导演：Tempo=Punish（其他敌人停手，让出舞台）
      → 表现：破衡爆闪 + 震屏 + 失衡条爆裂 + UI 提示"可连携"
  → 玩家在窗口内输入连携（或普攻继续压伤害）
      → 连携技 = 复用技能轴（专用 13000 段 SkillId + 入场相机意图）
      → 连携结束/窗口到期 → 敌人 Recover 起身（短暂无敌防无限连）
      → 导演回 Build Tempo，循环继续
```

### 1.4 与现有系统的接缝（必须守住的约定）

- 失衡是**计量条**：满条前只是数字，满条才转行为态；不建平行 Buff 运行时类型。
- 失衡硬直走 `CombatStateDirector` 的 **Control 系新槽位**（优先级：Dead > Control > Stagger > Hit > Skill > Locomotion 附近），不与眩晕/冻结抢同一判定；眩晕等硬控仍可覆盖失衡。
- 断招仍走 `CombatInterrupt` 比大小——失衡条满的断招是**无条件**的（独立的进入路径，不参与抗打断比较）。
- 敌人 HFSM 的 `Stagger` 态是**强制态**（`TryResolveForced` 优先同步），恢复走 `Recover` 起步逻辑。
- 表现不许在 `DamageAction` 里播；失衡 UI 事件走表现层订阅。

### 1.5 完成后的效果

- 打杂兵：几刀打满失衡 → 怪硬直跪下 → 连携/爆发窗口，节奏有"段落感"；
- 打精英：失衡条长、窗口短，需要规划段号与失衡贡献，战斗从"磨血"变"规划爆发"；
- 破衡瞬间的震屏 + 全局 Punish 静场 = 绝区零式"全场让位给这一击"的戏剧性；
- **验收**：F 键测（杂兵失衡 2 次普攻满、精英需重击段）、破衡后其余敌人停手、窗口内连携技可触发、到期起身无敌防连。

### 1.6 里程碑

| 步 | 内容 | 验收 |
|---|---|---|
| 1 | 段表 `DazeValue` + `CombatBreakMeter` 挂杂兵/精英 | 命中涨条，UI 显示 |
| 2 | 条满 → BreakSkill → Stagger 态 + 导演 Punish | 破衡全场让位、怪硬直 |
| 3 | 连携窗口 + 连携技（复用技能轴 + 入场相机意图） | 窗口内触发连携演出 |
| 4 | 破衡表现包 + 失衡条 UI 正式化 | 观感完整 |
| 5 | 失衡抗性、窗口时长按档位配表 | 难度可调 |

## 二、属性异常积蓄 → 异常触发 → 紊乱（P1）

### 2.1 目标

复刻绝区零属性体系：每个角色/招式带属性（物理/火/冰/电/以太），攻击积累对应**异常积蓄**，满条触发**属性异常**（灼烧/冻结/感电/侵蚀/强击），两个不同属性异常共存时触发**紊乱**（Disorder）结算爆发伤害并清空。

### 2.2 框架与结构

- `CombatMeterComponent`（挂实体）：**与失衡条同构**的通用计量组件——`Meter[元素]` 多条并行 + `Daze` 一条，统一由伤害段表喂值。失衡条(一)落地后，本组件应**合并/复用**其实现，不写第二套。
- 段表新增 `AnomalyType` + `AnomalyValue` 列（段级属性与积蓄贡献）。
- 异常状态本体**不新建平行系统**：满条后走现有 `AddStatusAction` 挂标准状态 Buff（灼烧 31011 等已存在）+ 独立伤害来源标签。触发条件用 `BuffTrigger`（现有组件），不写 `if (元素)`。
- 紊乱 = 结算规则层：检测"已挂属性异常 ≠ 新触发属性"→ 发独立 `DamageAction`（来源 `AnomalyBurst`，独立飘字、独立加成隔离）→ 按规则清旧异常（走 `RemoveStatus(Consumed)`，Buff 文档 §3）。

### 2.3 整体流程

```
伤害段结算 → 按段表属性向对应 Meter 加积蓄（可被异常抗性缩小）
  → 某元素条满 → 触发该属性异常（挂标准状态 Buff + 异常爆发伤害）
      → 若目标已有另一属性异常 → 紊乱结算：
          独立 DamageAction(DamageSource=AnomalyBurst) → 旧异常 RemoveStatus(Consumed)
  → UI：敌人血条旁元素积蓄条 + 异常图标（不进 Buff 图标栏，Buff 文档 §4）
```

### 2.4 接缝

- 依赖 Buff 文档 C/D/E/G 四项一起做：**伤害来源细分**（`Skill/DoT/AnomalyBurst/Coordinated/Shield`，独立飘字与"不触发自身"过滤）、**`TryConsume` 吃层 API**、**快照 Snapshot**（异常伤害锁触发瞬间属性，谁上的谁拿击杀）。
- 冻结等异常若与现有冻结 Buff（20601）重合，**复用同一条**，不做第二套表现。

### 2.5 完成后的效果

- 角色/招式有了属性身份，配队与技能选择出现"打什么条"的决策；
- 紊乱爆发的独立飘字 + 特效让"双异常互爆"成为可读的高光时刻；
- **验收**：单元素满条触发异常、双元素触发紊乱、紊乱不吃"命中点燃"类加成、击杀归属正确。

### 2.6 里程碑

| 步 | 内容 |
|---|---|
| 1 | `CombatMeterComponent`（含失衡条合并）+ 段表属性列 |
| 2 | 满条挂异常 Buff + 异常表现（专用 UI 条） |
| 3 | 伤害来源细分 + 独立飘字 |
| 4 | 紊乱结算 + `TryConsume` + 快照归属 |
| 5 | 抗性/积蓄速率配表化 |

## 三、黄闪招架（弹招 / 极限支援）（P0）

### 3.1 目标

补全攻防三角的"挡"：敌人黄闪招式**可被招架**，成功招架 = 打断或重硬直 + 全场 Relax（回合让出）+ 失衡贡献；红闪仍必须闪。只学绝区零黄红闪，**不做鸣潮收缩金圈弹刀**（已拍板）。

### 3.2 框架与结构

- 招式身份：`EnemyMoveSet.TelegraphKind = Parry`（枚举已存在）的黄闪招，轴上前摇摆 `AiTelegraph` 消息；**判定窗**用轴上 GrantTag 推 `Ai.Parryable` Tag（进入判定段才可招架）。
- 玩家招架技能：新 `SkillId`（走普通技能槽），入轴即开启极短**招架窗口**（前几帧为有效帧，参考现有闪避窗口写法）；窗口内受击且伤害源带 `Ai.Parryable` → 招架成功。
- 成功结算：打断当前敌人轴（`BreakSkill`，独立于抗打断比较）→ 敌人进重硬直 → `NotifyAttackWhiff` 同类通知导演 → **Relax（时长对齐完美闪 0.45s）** → 按段表给失衡贡献（接 §一）。
- 失败结算：招架窗口没兜住 = 正常受击；黄闪招不吃招架时（窗口错过）按 `Unblockable` 处理会造成困惑，故黄闪招**判定窗只可闪或招架**，招架失败的代价与普通受击相同（不做额外惩罚）。

### 3.3 整体流程

```
敌人黄闪招前摇（黄 Telegraph + 提示音）
  → 判定段 GrantTag Ai.Parryable
  → 玩家在窗口内按招架键 → 招架技能入轴
      → HitPipeline 命中招架窗口角色：源带 Parryable → 招架成功
          → 敌人 BreakSkill + 重硬直 → 导演 Relax → 失衡贡献 + 飘字"招架"
      → 窗口错过 → 按黄闪招正常判定（可闪）
```

### 3.4 接缝

- 玩家侧走既有 `ActSpellComponent.Enqueue → Gate → Session → XC` 唯一出招口；招架判定挂在 `CombatHitResolver` 后置点，**不写 `if (技能名)`**，一切问 Tag 与来源标签。
- 招架成功通知导演走现有 `NotifyPlayerDodge` 同类接口（AI 文档 §4.5 已预留语义）。

### 3.5 完成后的效果

- 攻防博弈三角闭环：黄=挡、红=闪、白=硬吃，敌人招式身份第一次有了玩法含义；
- 招架成功那一帧：敌人轴断 + 全场静默 + 失衡条涨，反馈强度对齐完美闪避；
- **验收**：黄闪招可招架、红闪招架无效、招架成功全场 Relax、窗口错过正常受击。

### 3.6 里程碑

| 步 | 内容 |
|---|---|
| 1 | 新黄闪敌人招（`TelegraphKind.Parry`）+ 轴上 `Ai.Parryable` GrantTag |
| 2 | 玩家招架技能 + 窗口判定 + 成功/失败分支 |
| 3 | 成功结算（打断/Relax/失衡贡献）+ 招架飘字/表现 |
| 4 | 支援招架形态（接 §四 快速支援，若做小队） |

## 四、小队换人连携（P1，先拍板）

### 4.1 定位决策（开工前必拍）

| 路线 | 说明 |
|---|---|
| A 单角色 ACT（推荐先拍这条） | 换人=换操作角色，不做队友；§四 整节降级为"多角色切换体验" |
| B 三人小队（ZZZ 本体） | 快速支援 + 入场技 + 延奏光环 + 喧响共享，工作量一个量级 |

本文按 B 写完整方案，若拍 A 只做 4.2 的子集。

### 4.2 框架与结构

- `TeamManager`（或并入 `PlayerManager`）：3 槽位、出场/候场状态、候场角色隐藏与暂停 Tick（Buff 文档 §9 的退场约定）。
- 换人流程复用现有 `SwitchCooldown`；新增两种触发：
  - **快速支援**：玩家受击/特定 ActionPoint 后提示换人（支援窗口），换入角色打**入场技**（复用技能轴 + `SwitchIn` 表现包 + 相机意图进场）。
  - **极限支援**：黄闪招的换人版本——§三的招架在三人队下由候场角色执行（入场即招架），成功结算同 §三。
- **延奏光环**：退场时 `TransferByTag("Buff.Outro")` 把指定 Buff 转移给下场角色（Buff 文档 §9 已定义方向），候场角色状态列表暂停 Tick。
- 喧响值（团队大招资源）见 §六·3。

### 4.3 整体流程（换人一次）

```
玩家换人输入（或支援提示窗口内输入）
  → 当前角色退场：收轴/挂 Outro 转移 → 隐藏 + 状态暂停
  → 换入角色：出场演出（SwitchIn 包 + 相机意图）→ 接手焦点
  → 快速支援：换入即入轴打入场技；极限支援：换入即招架窗口
  → 换人冷却（现有 SwitchCooldown）开始
```

### 4.4 接缝

- 全部走现有换人 API 与 `BuffExpirePolicy.OnSwitchOut`（枚举已占位，未挂钩）；
- 入场技 = 普通技能轴，不新增技能运行时。

### 4.5 完成后的效果

- ZZZ 式"被打→支援反击→换人继续压"的团队节奏；换人不只是切模型，而是攻防决策的一部分；
- **验收**：快速支援反击成立、延奏 Buff 正确转移、候场角色不跑 Tick、冷却阻止连换。

### 4.6 里程碑

| 步 | 内容 |
|---|---|
| 1 | 三槽管理 + 候场暂停 + 常规换人体验打磨 |
| 2 | 快速支援触发与入场技 |
| 3 | 极限支援（接 §三） |
| 4 | 延奏光环 + Outro 转移 |
| 5 | 喧响共享大招（接 §六·3） |

## 五、Boss 相位与屏外公平（P1/P2）

### 5.1 Boss 相位

- **结构**：Boss 档在敌人 AI 的第三档（`PhaseMask` 字段已预留，`PhaseIndex` 写死 0）；HP 阈值（如 70/40%）升相位，只升不降。
- **流程**：HP 越阈值 → 导演/Brain 通知 → 播放过渡轴（可复用时停表现包 `UltimateCinematic` 的时停语义）→ `PhaseIndex++` → 后续选招按新 `PhaseMask` 换招式池 → 新相位可增 `AllowMeleePlusSpecial`、更换保持距离与 Recover 参数。
- **效果**：Boss 战有阶段感，每个相位招式池/节奏不同；**验收**：阈值触发、过渡轴不被打断（或按设计可打断）、招式池确实切换、不进站位槽。

### 5.2 屏外公平

- **结构**：导演侧两条规则——屏外敌人**发牌硬禁**或 `OffscreenDelay`（回到屏内后延迟 X 秒才可出手，AI 文档 §12.1 P0 已列）；屏外持牌者显示**攻击方向指示器**（屏幕边缘箭头，ZZZ 同款）。
- **流程**：`IsOnScreen`（5%~95% 视口）为假 → 不授予真伤 Token / 延迟计时；恢复屏内 → 计时结束可重新竞拍。
- **接缝**：画幅判定在相机 Stage 2 落地后用真实画幅，不再依赖 `Camera.main` 粗判。
- **效果**：玩家永远不会被"看不见的怪"偷袭，屏幕边缘有明确威胁方向。

### 5.3 部位破坏（可选，挂在本节）

ZZZ 部分精英有部位破坏（破坏特定部位换弱点/硬直）。方案：精英身上挂 `PartBreakComponent`，部位 = 独立小计量（复用 §二 计量组件），破坏触发局部硬直或弱点增伤，表现走部位特效。**P2 可选，不做不影响主循环。**

## 六、表现与资源体系补全（P2）

### 6.1 Telegraph 正式资产

- 现状：占位四角星 + 颜色/时长已通（`CombatTelegraph.Shown` 事件已留、无人订阅）。
- 方案：订阅 `Shown` 事件播放正式特效（黄/红/青/暖白各自的特效 + 提示音），特效池复用 `RunTimePoolManager`；12001/12003 平劈改轴上 `AiTelegraph` 或 `TelegraphKind.None` 减噪声（AI 文档 §12.3 第 1 条）。
- 效果：前摇语言完整（视觉 + 听觉），玩家凭提示即可读招。

### 6.2 敌人正式动画

- 现状：借用玩家剪辑，动作与位移不对位。
- 方案：敌人专用 Animator 控制器 + 对位动画替换；动画资产上线后，`EnemyMoveSet` 的轴引用同步切换（12000 段轴只换资产不换结构）。
- 效果：杂兵/精英观感独立，前摇/位移/受击可读性上一个台阶。

### 6.3 喧响值（团队大招）与 EP（特殊技能量）

- 现状：有 `CheckIsHadEnoughEnergy` 接口、`ResourceAction`、`Ultimate` 槽位与 `UltimateCinematic` 包，但**没有完整资源条体系**。
- 方案（结构）：
  - **喧响值**：团队级计量（复用 §二 计量组件），由连携/极限闪避/招架等"高光行为"增长；满条解锁大招，大招消耗整条。大招本身复用技能轴 + 时停演出包，**不新建技能运行时**。
  - **EP（特殊技能量）**：角色级计量，普攻/命中回复、特殊技消耗；消耗判定接现有 Gate（`AbilityActivationGate` 处查资源）。
  - 两条都做成**资源条 UI**（不是 Buff 图标），随伤害来源与 ActionPoint 增长。
- 效果：大招从"无成本技能"变"资源决策"；连携→喧响→大招形成完整的高光链（§一 → 本项）。

### 6.4 受击反应分级表现

- 现状：`CombatHitReaction` 只做入口（闪白/顿帧按段表 `HitReactionType`），短硬直 0.35s 一刀切。
- 方案：`HitReactionType` 分级落地为表现差异——轻（原地小硬直）、重（后仰/退步）、击飞（浮空/击退 + 相机 Kick 增强）、失衡（§一 的 Stagger 专用）。分段表列配置，表现走 `CombatPresentationDirector`。
- 效果：不同段的"打中感"有层次，重击段和失衡段一眼可辨。

## 七、小项合集（P3）

### 7.1 硬控互斥（Buff 文档 §10 尾项）

新硬控落地时替换旧硬控或按 Priority 覆盖（在 `PreReceiveStatus` 阶段做）。防止"眩晕叠冻结"双重图标、行为混乱。

### 7.2 快照 Snapshot 与刷新归属（Buff 文档 §7）

DoT/异常伤害锁定"施加瞬间"的属性快照（`RefreshDuration / KeepStrongerSnapshot / ReplaceCaster` 三策略配表化）；击杀归属算快照主人。异常体系（§二）的数值正确性依赖此项，建议与 §二 同步做。

### 7.3 Peak 压力态 / 威胁表 / 远程敌人（AI 文档 P3）

- Peak：连续受击/久不闪避时临时 Melee+1（压力旋钮，接口已在 Tempo 枚举）；
- 威胁表：多焦点仇恨（单机收益低，后做）；
- Ranged：远程 Token 发牌与弹道招（`TokenKind.Ranged` 枚举已占位）。
